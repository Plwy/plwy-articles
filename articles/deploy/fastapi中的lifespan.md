> 注意：
>
> `lifespan` 中的 `yield` **不是为了“保持模型存活”** 。`yield` 是为了让 FastAPI 知道：“启动任务完成了，现在可以开始处理请求了”。

#### `lifespan` 的工作原理

`lifespan` 是一个**异步上下文管理器（asynchronous context manager）**。它的结构必须是：

```python
@asynccontextmanager
async def lifespan(app: FastAPI):
    # --- Startup 阶段 ---
    # 这里写应用启动时要做的事（如加载模型）
    # ...
    
    yield  # ← 这是关键！应用在此处“暂停”，开始接收请求
    
    # --- Shutdown 阶段 ---
    # 这里写应用关闭时要做的事（如清理资源）
    # ...
```

- **`yield` 之前**：执行**启动（startup）** 逻辑。只有当这部分代码执行完毕后，FastAPI 应用才会正式启动，开始监听和处理 HTTP 请求。
- **`yield` 之后**：执行**关闭（shutdown）** 逻辑。当服务器收到关闭信号（如 `Ctrl+C`）时，会执行 `yield` 之后的代码，然后完全退出。

#### 为什么 `yield` 不可或缺？

即使你的模型是单例、加载一次就永久缓存，`yield` 仍然必不可少，因为：

| 原因                 | 说明                                                         |
| -------------------- | ------------------------------------------------------------ |
| **框架契约**         | FastAPI 期望 `lifespan` 是一个上下文管理器。`yield` 将函数分割为“启动”和“关闭”两部分。没有 `yield`，就不是一个有效的上下文管理器。 |
| **控制应用启动时机** | `yield` 是一个“分水岭”。**在 `yield` 之前，应用不会开始处理任何请求**。这确保了你的模型在第一个请求到达前就已加载完毕。 |
| **支持优雅关闭**     | `yield` 之后的代码会在应用关闭时执行。即使你不需要清理，`yield` 也提供了这个可能性（比如释放 GPU 显存、关闭数据库连接等）。 |
